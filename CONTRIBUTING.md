# Как вносить правки

Документ описывает порядок внесения изменений в репозиторий: именование
веток, пул-реквесты, проверки CI и требования к коммитам. Сборка,
необходимые инструменты и устройство дерева описаны в [README](README.md).

## Ветки и пул-реквесты

- Изменения попадают в `main` только через пул-реквест, у которого успешно
  пройдены все обязательные проверки CI. Набор правил (ruleset) ветки
  `main` на GitHub запрещает прямой push и force-push, требует линейной
  истории и допускает вливание только способами rebase и squash. После
  вливания GitHub удаляет ветку пул-реквеста автоматически.
- Изменение разрабатывается в отдельной ветке с именем `bukvitsa-<тема>` из
  строчных латинских букв и дефисов. Пул-реквест открывается из этой ветки
  в `main` и содержит изменения одной темы.
- Если ветка пул-реквеста отстала от `main`, обновите её кнопкой
  «Update with rebase». Слияние `main` в ветку не допускается: проверка
  отклонит коммит слияния.

## Проверка (CI)

Workflow [`.github/workflows/ci.yml`](.github/workflows/ci.yml) выполняется
на раннере Windows. Он собирает дерево в конфигурациях Debug и Release,
запускает тесты и открывает окно читалки.

- Библиотека wxl используется на коммите, указанном в
  [`tools/wxl.json`](tools/wxl.json). Задание `wxl-revision` проверяет, что
  этот коммит входит в `main` репозитория wxl. Если изменению нужна более
  новая версия wxl, коммит в `tools/wxl.json` меняется после того, как
  нужное изменение wxl влито в её `main`; до этого проверка `wxl-revision`
  завершается ошибкой.
- Обязательные проверки: `build (Debug)`, `build (Release)`, `wxl-revision` и
  `commits`.

## Коммиты

Сообщение коммита пишется по-русски связным текстом: что изменено и почему.
Задание `commits` проверяет каждый коммит пул-реквеста на соответствие
правилам ниже; в сообщении об ошибке указан номер нарушенного правила.

1. Адреса электронной почты автора и коммиттера имеют вид
   `…@users.noreply.github.com` (настройка «Keep my email address private»);
   совпадать они не обязаны. Коммиттер `GitHub <noreply@github.com>`
   допускается только у коммита, подписанного самим GitHub.
2. Сообщение коммита не содержит строк `Co-Authored-By` (у коммита один
   автор), строк-баннеров и строк-трейлеров со ссылками.
3. Скрытые каталоги и файлы (с именем, начинающимся с точки) в репозиторий
   не добавляются, за исключением перечисленных в проверке.
4. Подписывать коммит не обязательно; если подпись есть, GitHub должен её
   подтверждать (Verified).
5. Коммиты слияния не допускаются: история линейная.

## Перед пул-реквестом

Перед открытием пул-реквеста достаточно собрать и проверить в конфигурации
Debug только то, что затронуто изменением; полную матрицу конфигураций
проверяет CI. Команды выполняются из корня дерева:

```
tools\build.ps1 -Target <цель>
ctest --preset x64-debug -R <тест>
```

Тесты: `fb3_tests`, `mathml_tests`, `typography_tests`, `system_failure.*`,
`bukvitsa_lib_tests`, `bukvitsa_imaging_pool_tests`; читалка — цель `Reader`.
