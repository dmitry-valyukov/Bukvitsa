# Как вносить правки

Правила одни для всех, кто вносит правки. Сборка, предпосылки и устройство
дерева — в [README](README.md).

## Ветки и пул-реквесты

- `main` меняет только пул-реквест с зелёным CI. Его держит набор правил
  GitHub: прямого пуша и force-push нет, история линейная, вливание — только
  rebase или squash, ветку влитого пул-реквеста GitHub удаляет сам.
- Ветка — `bukvitsa-<тема>`, строчными буквами через дефис; пул-реквест — из
  неё в `main`; одна тема — один пул-реквест.
- Отставшую ветку пул-реквеста обновляйте кнопкой «Update with rebase», а не
  слиянием `main` в ветку: коммит слияния проверка отклонит.

## Проверка (CI)

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) на машине Windows
собирает дерево в Debug и Release, гоняет тесты и открывает окно читалки.

- wxl берётся на коммите из [`tools/wxl.json`](tools/wxl.json), и задание
  `wxl-revision` требует, чтобы этот коммит был в `main` wxl. Правка, которой
  нужна более новая wxl, передвигает закрепление, когда нужная ей правка wxl
  уже влита в `main` wxl; до того `wxl-revision` красная.
- Обязательные проверки: `build (Debug)`, `build (Release)`, `wxl-revision` и
  `commits`.

## Коммиты

Сообщение — по-русски, простым рассказом: зачем и почему. Остальное задание
`commits` проверяет в каждом коммите пул-реквеста, под этими номерами:

1. Адреса автора и коммиттера — вида `…@users.noreply.github.com` (настройка
   «Keep my email address private»); совпадать они не обязаны. Коммиттер
   `GitHub <noreply@github.com>` допустим только на коммите, который GitHub
   сам подписал.
2. Без строки-трейлера `Co-Authored-By` (у коммита один автор), без
   строк-баннеров и без строк-трейлеров со ссылкой.
3. Скрытые каталоги и файлы (`.…`) в дерево не входят, кроме перечисленных в
   проверке — ровно тех, что дерево хранит.
4. Подпись — только та, что GitHub проверяет (Verified); неподписанный коммит
   проходит.
5. Коммитов слияния нет: история линейная.

## Перед пул-реквестом

Локально собирайте и проверяйте только то, что задела правка, в Debug;
полная матрица — дело CI. Из корня дерева:

```
tools\build.ps1 -Target <цель>
ctest --preset x64-debug -R <тест>
```

Тесты: `fb3_tests`, `mathml_tests`, `typography_tests`, `system_failure.*`,
`bukvitsa_lib_tests`, `bukvitsa_imaging_pool_tests`; читалка — цель `Reader`.
